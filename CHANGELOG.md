# Changelog

User-visible changes to Justless are recorded here. No release has been published yet, so the Unreleased section describes what the `main` branch does today. When a version is tagged, its entries move under that version's heading.

## Unreleased

### Command output

- Searches with context options, such as `rg -n -C3`, `grep -rnA5` or `git grep -n -B2`, report blocks: each file's match and block counts, its first block exactly as printed, and its other blocks with their line ranges and `[stdout:A-B]` tags that `justless log` replays exactly. `justless run` showed only the matching lines of such a search, and Claude Code's post-command hook passed it through whole. Single-file `grep -n` and `rg -n` output without file names, `rg --heading -n` and file names with dashes or colons are read; output with any other line keeps the ordinary preview, and the post-command hook passes it through. Through the post-command hook, seven such searches over this repository's sources, of 5 to 12 KB each, went from 54,940 bytes to 16,045 with their run markers. In `justless run`, the block report is larger than the matching lines it replaces.

- Claude Code can compact mixed Bash read lists after execution. Each verified command gets its own preview and line range, and one `justless log` replays the combined output.

- Wide single-file `sed -n 'A,Bp' FILE` (with one or several ascending ranges), `head -n N FILE`, `tail -n +N FILE` and, in Claude Code, `tail -n N FILE` hook reads can show a range outline and a command to replay the original bytes. Replays count toward net savings in `stats`.

- `git show REV:path`, `git show REV:./path` and `git show :path` show an outline of the file as that revision or the index holds it, with a command to replay the original bytes, when the blob is wide and the parsers outline it, on its own or as a piece of a Claude Code read list. Claude Code's hook checks the printed bytes against the blob. Other shell clients get a read pinned to the blob id. Read lists now accept revisions such as `HEAD~1`.

- `justless run -- COMMAND` runs a noninteractive command and keeps its exit status. It shows a bounded preview of stdout and stderr and archives both streams under `.justless/runs/`, up to `max_run_bytes` each. `log` replays any line range byte for byte, `search` finds text in one run, and `history` searches every run in the project.
- `search` and `history` no longer cut off matches silently. When `--limit` or the budget leaves matches out, each stream with a match keeps a place, a failed run's failure lines and stderr come first, and a last line counts the matches shown and found per stream, such as `[20 of 26 matches shown (stdout 19 of 25, stderr 1 of 1); --limit 26 shows all]`. Under a very small `--budget`, `history` shortens that line to the totals so a match of each stream still fits. Earlier, 20 stdout progress lines could hide the stderr line that explained the failure. `lookup --logs` keeps a window for each stream with matches, counts the windows it leaves out per stream, and reports them as `logs` in `--json`. The MCP `search` and `history` tools return the same notice, and `recall ID --grep TEXT` counts the matching lines its `--limit` leaves out.
- `history TEXT` keeps a place for the first failed run it lists when the runs before it passed, so newer passing matches no longer hide an older failure, such as a merged run's `FAILED` line on stdout. Past 1000 matches, the most the MCP tools take as `limit`, the `search` and `history` notices suggest a narrower TEXT, one `--stream` or `--oldest` instead of a `--limit` the MCP tools would reject.
- Test failures from `cargo test`, `go test` and `pytest` are grouped by their reported diagnostic. Each group links to its lines in the archived log. The JavaScript runners `npm`, `pnpm`, `yarn` and `bun test`, `jest`, `vitest run` and `node --test` drop passing-file lines and keep failures.
- Compiler and linter findings are grouped by rule across both streams, with a count, the first message and up to four locations. Errors keep the detail of their first occurrence. Recognized tools include rustc and Clippy, Ruff, flake8, pylint, mypy, Pyright, ESLint, `tsc`, ShellCheck, golangci-lint, `go vet`, staticcheck, RuboCop, SwiftLint and hadolint. Package runners such as `npx`, `uv run` and `bundle exec` select the same grouping.
- Large search output from `rg`, `git grep`, `ag`, `ack` and recursive `grep` is grouped by file, with match counts and the first matching lines exactly as printed. File listings from `find`, `fd`, `tree`, `git ls-files`, `ls -l` and `ls -R` are grouped by directory. Matches and entries inside dependency and build directories collapse into one line each. Small output stays verbatim.
- JSON arrays of objects, JSON lines and objects holding such arrays reach the agent as tables that name each field once and lift fields every record shares, such as a synthetic 40-issue `gh api` listing cut from 21.7 KB to 14.5 KB or 25 `docker ps --format '{{json .}}'` lines from 7.3 KB to 1.4 KB. Every table is decoded back and must equal the original data, keeping `null` apart from a missing field, `"1"` apart from `1`, key order and escapes, or the ordinary preview stays. Only output that reaches the agent directly, or is clipped anyway, is reformatted, so a typed `justless run -- cmd | jq` keeps working. `json_grouping = true` also groups consecutive rows that share a value.
- `git show` and `git log -p` patches are summarized like `git diff`: each commit's header, with its subject, is one item before that commit's file and hunk items, and every item links to its exact `[stdout:A-B]` lines. They showed only a clipped head and tail before, because the summary required `diff --git` first. With a 4 KiB budget on this repository, a 11,462-byte `git show` went from a 2,046-byte head and tail to a 1,008-byte summary. Larger commits, of 34 to 231 KB, get summaries of 2.6 to 4.0 KB, larger than the 2 KB head and tail they replace, that name every hunk and describe a 49-package `Cargo.lock` change. A rerun that shows only other commits, as `git show HEAD` does after a commit, is not compared with the earlier one. Output with `--stat`, `--oneline`, a custom `--format`, a merge's `diff --cc` or no patch keeps the ordinary preview.
- A `git diff` or `git show` that covers `Cargo.lock` names the packages added, removed and updated and the dependency links that changed, read from both revisions, instead of listing lockfile hunks, when that is smaller. A `source` or `checksum` change on an existing version is always flagged at the top, even when the rest is clipped, and `justless log` keeps the exact patch.
- Git diffs are summarized by hunk. `docker ps` and `kubectl get` for pods, deployments, statefulsets and nodes count the rows and name the ones that need attention, and `docker logs` and `kubectl logs` collapse repeated lines.
- A rerun of the same command in the same directory and session shows which failures, rules, hunks, files or directories appeared, changed or disappeared. Identical output can collapse to one line.
- Hook-routed runs print a footer only when it adds information: when output was shortened or when the command failed. On 13 routine commands, the earlier footer added 29.1% to the bytes an agent received, and the current one adds 3.7%.
- `[[filters]]` entries in `.justless.toml` omit known noise lines from a command's preview. Lines that look like failures are always kept.
- `run` exits like a shell: 127 for a command that is not found and 126 for one that cannot run. Without a writable state directory the command runs uncaptured after one warning, and once it has started, its output and status come back even if `.justless/` is deleted during the run.
- SIGTERM and SIGHUP sent to Justless reach the command, and an interrupt sent to Justless alone is forwarded after 200 ms. A run whose Justless process was killed, as by a client that gave up on a hook-routed command, stays in `history` as unfinished and `log` replays its output so far, until retention deletes it like any other run.
- Every preview collapses carriage-return progress frames to the last frame, cuts base64 and hex runs of 200 and 160 characters or more to their ends and a length, and folds consecutive repeated lines into a count. Each cut says what it removed, lines that look like failures and patch lines are never touched, and a stream that fits is changed only for a hook-routed run.
- In Claude Code, the post-run hook also compacts a single unsupported command, such as `gh api` or a build script, when its inline output exceeds four context budgets: it gets the floor and JSON tables, never a clipped preview, and only when that saves a quarter. File readers and pipes pass through.
- A clipped preview lists failures first in `[diagnostics]`, such as a compile error after hundreds of warnings or a Python traceback through its exception, and every excerpt ends on a whole line.
- Each stream of a run stores at most `max_run_bytes`, 256 MiB by default, so a command that reads its own archive, such as `sh -c 'grep -rn x .'`, can no longer fill the disk. The command still runs to completion with its own exit status, and the footer and `log` say where the archive was truncated. On Unix, Justless returns when the command exits, and output that a background process writes later is still stored within the cap. On Windows, `run` waits until such a process closes the output.
- After each run, Justless keeps the newest `max_runs` runs within `max_archive_bytes`, and an unchanged rerun links to the streams of the run it matched instead of storing them again.

- Secrets in command output, such as cloud keys, tokens and private keys, are masked in previews, footers, `log`, `search`, `history`, `lookup --logs` and MCP results. The archive keeps the exact bytes, and `log --unredacted` returns them. Command lines that may carry a credential are not stored.
- `justless exec` runs a script an agent writes over large data, with the same archive and exit status as `run`. Long stdout shows whole head and tail lines and the range left out, and `--intent TEXT` ranks the lines that match it.
- `justless learn` reads recent Claude Code transcripts and proposes project rules from command mistakes agents corrected or repeated, such as an unquoted glob or a tool that is not installed. `--apply` writes them to a managed block in `AGENTS.md` or `CLAUDE.md`. Rules that could carry a credential are held back.

- `justless test --affected` runs only the tests that can reach the current Git changes, with Cargo, pytest, Jest, Vitest or Go, through the same capture as `run`. The result is labeled as a subset in the verdict and in `resume`, `history` and `stats`, and keeps the runner's exit status. It runs the full suite instead, and says why, for lockfiles, build or runner configuration, unindexed or unmentioned files, a changed symbol no test reaches or reaches only through inferred links, or a selection of 60% or more of the tests. `--dry-run` prints the plan, `--why RUN_ID` prints why each test ran, and `justless test` runs the full suite.
- Rust doctests are the code blocks rustdoc runs: fenced with backticks or tildes, unless the info string names another language, or indented, in `///`, `//!`, `/** */`, `/*! */` and `#[doc]` documentation. Changed documentation that holds an example runs its file's doctests, and documentation Justless cannot read, such as `#[doc = concat!(…)]` or doc comments inside a macro call, runs the crate's. An example also runs when it names anything the change reaches, such as the public function that calls a changed helper, the type of a changed method as common as `new`, or the name a `use … as` re-export gives it. A method's examples run under any generics rustdoc prints, and a doctest filter that matches nothing reruns the crate's doctests in full.
- `justless test --compare REF` tells the failures a change introduced from those already failing on the base branch. After the working-tree run it reruns only the failing tests, by exact name, at the merge base of `REF` and `HEAD` in a temporary Git worktree, removed afterwards, and groups them as new (passing at the base, or with no result there), changed (failing at the base with another message) or already failing with the same message. Cargo and pytest are supported, and `--affected` compares the subset. The exit status stays the working tree's. Cargo builds the base in its own target directory under `.justless/`, which later comparisons reuse; sharing the working tree's would make its next `cargo test` run the base's code.
- `test --affected --base REF`, `affected --changes --base REF` and `context --changes --base REF` review a branch: the changes run from the merge base of `REF` and `HEAD` to the working tree, so committed and uncommitted edits both count, and the plan header names the ref and the merge base. A ref that names no commit is an error, and a clean tree without `--base` says so and suggests it, naming a branch that exists here, instead of planning nothing in silence.
- A change Git lists without a line diff, such as a script that lost its executable bit, a fixture marked `-diff`, a binary, a symlink, a submodule or a change of type, no longer drops out of `context --changes`, `affected --changes` and `test --affected`. Each is listed with what changed, such as `mode 100755 -> 100644`, and `test --affected` runs the full suite with the reason `no-line-diff`. Before, such a change read as "No changed files" and the affected run passed without running anything.
- `test --affected` follows a change in a Vue, Svelte or Astro component, including one to a function in its script, to the Jest and Vitest test files that import the component, directly or through other components. A change that a function in a component calls reaches the component's importers too. A component that no test reaches runs the full suite with `no-tests`, and a deleted one with `deleted-module`. Code in a language Justless has no runner for, such as Elixir that reaches only its ExUnit tests, runs the full suite with `data-unlinked` instead of nothing, and a MATLAB `.m` file counts as data rather than Objective-C.

- Without `--max-bytes`, each command family's preview budget adapts to the project's own history. It doubles, up to four times `max_output_bytes`, when at least a quarter of five or more clipped runs had a clipped stream replayed in full, and halves, down to half of it, after 20 clipped runs that nobody replayed. A raise wears off once output fits one step down, a budget raised back after a lower waits twice as long before it is lowered again, and runners such as `npm run` and `sh -c` keep the default. Each step is judged only by the runs made since the previous one, an explicit `--max-bytes` always wins, and the family's rerun comparisons start fresh after each change. Set `adaptive_previews = false` in `.justless.toml` to turn it off.

### Code navigation

- `--root` given once before the subcommand and once after it with different directories is now an error. Before, the second silently won, so a command could run in the wrong project.
- A local index covers Rust, JavaScript, TypeScript and TSX, Python, Go, Java, Kotlin, Scala, Groovy, C, C++, Objective-C, C#, Swift, Dart, Ruby, PHP, Elixir, Julia, Lua, Zig, Bash, PowerShell, SQL and HCL, including Terraform. It refreshes on every query and reuses unchanged files.
- Vue, Svelte and Astro components are indexed through their scripts and Astro frontmatter, at their own line numbers, so `read --outline`, `query`, `path`, `affected`, `pack` and `lookup` see their functions, calls and imports. Extensionless scripts take the language of their `#!` line, Objective-C headers are recognized by `#import` and `@interface`, and `.m` files without them, such as MATLAB code, stay text. Objective-C++ `.mm` files are not indexed, since the Objective-C grammar found errors in 209 of 357 of them. Elixir, Objective-C, PowerShell, Julia and Groovy (with Gradle build scripts) have definitions, calls and their test conventions: ExUnit, XCTest, Pester, `@testset`, Spock and JUnit. The index cache is rebuilt once after the upgrade.
- `query`, `path`, `find`, `context` and `code` answer definition, reference, caller, test and dependency questions with a file and line for each result. Links inferred across languages, such as an HTTP route or a SQL table name, are marked as possible.
- `pack` gathers definitions, graph links, source lines, working-tree changes and recent failures for a task within a byte budget.
- `map` summarizes a repository's areas, hubs, communities, cross-area links, entry points and test locations.
- `affected` lists what depends on a symbol, a file or the current Git changes, hop by hop. It names the tests that reach the target and, for Rust, Python and Go layouts, a command that runs them. Deleted code is reported as a deletion rather than as a change to the line next to it. Code counts as still referencing a deleted symbol only when its path, an import or an alias resolves to the symbol, including inside a Rust macro call. A same-named function in another module no longer does, and a name match the index cannot resolve is marked possible.
- `context --run RUN_ID` connects a captured failure to its assertion, its enclosing symbol and the functions it calls.
- In a session, `context --symbol` and `context --at` print a symbol read before as only the lines that changed since, with two unchanged lines around each change, a line such as `45 of 46 lines unchanged since you read it at REV` and an `expand` command that prints the whole symbol. An unchanged symbol is one line. `pack` shortens excerpts it printed the same way before. The Claude Code hook adds `--session` to `justless context` and `justless pack` commands, from the session ID and, in a subagent, the subagent's ID, where the permission rules let it rewrite; the shell's `CLAUDE_CODE_SESSION_ID` is not used, because subagents share it. The compaction hooks or `--fresh` bring back whole views, and `stats` reports the bytes the deltas kept out. On a 46-line test with one line changed, the second view took 512 bytes instead of 2,039.
- `NAME@FILE:LINE` selects one of several definitions that share a name, such as cfg-gated twins.
- Rust paths into another crate of the repository resolve through the `path` its dependency names, directly, through `[workspace.dependencies]` or in a `[target.….dependencies]` table. A registry or renamed dependency that shares a workspace crate's package name, or an import such as `use upstream_ctrlc as ctrlc;`, is no longer linked to the local crate.
- An unreadable or oversized file is skipped rather than failing every query. `index` lists the skipped files, and a query or `find` that finds nothing names them.
- `find --path PATH` and `--glob GLOB` narrow a search to files and directories or to `rg -g` style globs, and the output names the scope it read. A path with no indexed files or a glob that matches none says so, instead of reading as no matches. A page cut by `--limit` or the budget says which bound cut it, such as `[budget reached after 5 of 60 matches in 58 files, before --limit 20]`, and prints the command for the next page with an `--after` cursor that is rejected if the search or the file it stopped in changed. `--json` returns the same pages, and the MCP `find` tool takes `path`, `glob` and `after`.

### Reads and edits

- Commands Justless prints for the agent to run next name a file that starts with `-` as `./-name.md`, and put search text that starts with `-` after `--`, so they no longer fail as unknown options.
- `read FILE --outline` returns a revision and numbered signatures with line ranges. `expand` returns the exact bytes of a symbol, Markdown section or line range.
- `edit` replaces or inserts at a symbol or line range only when the file still matches the revision the agent read. A batch of same-file edits is checked as a whole, and a stale, ambiguous or overlapping edit rejects the batch. `--dry-run` shows a diff.
- Without `--root`, `read`, `expand` and `edit` resolve a relative path from the current directory, falling back to the project root. `edit` refuses files the user cannot write and keeps hard links and extended attributes.
- A command Justless prints for the agent to run next, such as lookup's `Next:` line, a run footer, `test --affected`'s `Full suite:` and `Why:` lines or hook context, reaches the same workspace from the directory the agent works in. It adds `--root` with the absolute root when a plain `justless` there would find another one, as after `--root billing`, and for `read`, `expand` and `edit` also from a subdirectory. Before, `justless --root billing lookup` could suggest an `expand` that opened the repository root's file of the same name. MCP tool results always add `--root`, since the server cannot know where the agent's shell works. The `Full suite:` line repeats the runner given after `--`.
- An outline of Rust source with a syntax error names the error and its line.
- Markdown outlines and `lookup` sections follow the CommonMark heading rules. A heading underlined with `=` or `-` starts its own section, so expanding or editing the section above it no longer takes it along. `#tag` lines and lines in code, HTML blocks, front matter, block quotes and list items are not headings.
- `edit` rejects a batch that would leave a parsing file unparseable and leaves the file unchanged. It exits 2 with the parser's line, column and message, a few lines around them and the flag that writes it anyway, `--allow-parse-errors`. `--dry-run` gives the same verdict. Rust is checked with syn, and any error it finds rejects the batch. The other indexed languages except SQL are checked with Tree-sitter, whose bundled grammars can lag behind newer syntax, so an error there rejects the batch only when a token is missing or the edit leaves brackets that no longer pair up. Other errors, and any error in C, C++, shell, Objective-C, PowerShell, Julia or Groovy, whose grammars reject much working code, are written with a warning on stderr. In downloaded releases, those four newer grammars found errors in 8% to 30% of the files, and the Elixir grammar in none of 1,376, so Elixir edits are checked like Python's. A `.m` file without Objective-C markers, such as MATLAB code, is not checked. A file that already failed to parse is never blocked, and stderr says whether the edit fixed it. The check added 37 ms to a dry-run edit of a 690 KB Rust file.
- Claude Code's Read hook outlines a whole text Read of a parser-supported file outside the workspace from the text Read returned, archives the original so the first line names `justless recall ID`, and points to a Read of at most 150 lines or `allow_large` for the lines. Dotfiles, `$HOME/.*` and Claude Code's saved tool results pass through. A 35,392-byte Rust file from another checkout came to 2,764 bytes.

### Tool history and sessions

- `mask` retires older tool results in an outbound request to `[justless recall ID]` references, and `recall` restores the original value. The OpenCode v1 plugin applies this automatically before each model request.
- Claude Code and Codex hooks carry recent run IDs, outcomes and inspected file ranges across compaction, within 1,800 bytes. `resume` shows the same handoff from the terminal. Runs are named by their command, such as `git status` or `cargo test`.
- `read` of a small file, which prints it whole, is recorded in `resume` and the handoff as `Read FILE:1-N`, like `expand` of the same lines, and marked `[source changed]` once the file changes. An outline from `read` or the Claude Code Read hook is listed as `Outline FILE`, and the Read hook records the lines of each Read it passes through.

### Agent setup

- `.justless/` holds its own `.gitignore`, so archived output stays out of `git status` even in a project that never ran `justless init`.
- `install.sh` installs a checksum-verified prebuilt binary when a release exists for the platform, and otherwise builds from source. Run from a project, it sets up every detected agent. It does not set up hooks when run from the home directory or `/`.
- `justless doctor` checks that `justless` on `PATH` is the running version, finds each agent's CLI, and compares the project's hooks and instruction blocks with what `init` writes now, naming missing hooks, changed matchers and older blocks. It also checks MCP entries and `.justless/`, and shows when hooks last routed a command. In a Justless checkout it warns when the copy hooks run was built from an older commit, using the Git revision `--version` now prints on a second line. Each problem comes with a command to run or an edit to make, and `--json` returns the same checks. It only reads, and it exits 1 while something needs fixing.
- `justless init --hooks` configures Claude Code, Codex, Cursor, Gemini CLI, GitHub Copilot CLI, Antigravity CLI and OpenCode. It keeps existing instructions and settings, and running it again is safe.
- Hooks rewrite supported commands, including inside `&&`, `||` and `;` lists, and leave pipes, other redirections and machine-readable output alone. The Codex, Cursor, Copilot and Antigravity hooks pass a list through unchanged when it also contains an unsupported command, and every hook passes through a list that changes directory other than with a plain `cd DIR` inside the workspace. The Claude Code hook leaves `grep` to Claude Code's gitignore-aware shell and passes through commands started with `run_in_background`. A command that starts inside a nested Git repository or submodule is rewritten with `--root`, so its run stays in the workspace archive.
- Hooks route supported commands that start with `NAME=value` assignments or end with `2>&1`, as agents often write them: `RUST_BACKTRACE=1 cargo test 2>&1` runs as `RUST_BACKTRACE=1 justless run --hook --merge -- cargo test 2>&1`. The variables still reach the command, and the exit status is kept. With `--merge`, the command writes stdout and stderr to one pipe, which Justless archives as stdout within `max_run_bytes`, so output shown in full arrives byte for byte in the order the command wrote it. A merged run keeps its own preview rather than a test, patch or inventory summary of stdout, and a merged search or listing keeps its streams apart and says so in its footer. Assignments to `PATH`, zsh's `path`, `LD_*`, `DYLD_*` or `JUSTLESS_*` pass through, and so does a list in which an earlier command sets, exports or unsets one of them, such as `PATH=/x; cargo test`. The Codex, Cursor, Copilot and Antigravity hooks accept only display and diagnostic variables such as `RUST_BACKTRACE` and `NO_COLOR`, and no assignment before `make`. On this repository's own Claude Code transcripts these forms route 9 more commands with 5,840 bytes of output, while pipes still pass through far more. A captured run flushes a final stdout line that has no newline before it prints stderr, so a merged stream keeps the footer last. [Measurements](docs/benchmarks.md#assignments-and-a-final-21)
- Codex and Cursor approve a rewritten command without asking, so their hooks rewrite only commands that run a local tool directly, with conventional build and test targets, a short list of display options and no argument outside the working tree. Other commands, such as deploy targets and package-runner downloads, pass through to the client's own approval.
- Hooks route Git revisions that contain a tilde, such as `git diff HEAD~3` and `git log main~5..HEAD`. A `~` passes through only where the shell expands it: at the start of a word or after `=` or `:`.
- The instruction block that `init` writes into `CLAUDE.md`, `AGENTS.md` or `GEMINI.md` is 1,024 bytes between its markers, down from 1,856, because agents load it with every request. It tells them to run supported commands plainly, to wrap one command in `justless run` when long output arrives raw, to recover archived output with `search`, a ranged `log` or `context --run` instead of rerunning, and which search fits a question: `find` for literal text, `query` for symbols, `lookup` for where something is set and `rg` for regular expressions. It also says that `context` and `pack` re-reads show only changes and that `--fresh` shows all. Run `justless init` again to replace the block in an existing project. When `CLAUDE.md` links to `AGENTS.md`, `init` edits the linked file once.
- Claude Code's post-command hook compacts large Bash output that the command hook left alone, such as `cargo test 2>&1 | tail -200`, `RUST_BACKTRACE=1 cargo test | tail` or Claude Code's own `grep -rn`, after the command ran. It archives the output as a run within `max_run_bytes` and shows the preview `justless run --hook` gives the same command, followed by any error lines the preview left out and the run marker, with secrets redacted as in any preview. Failing commands, file readers, reshaping filters such as `cut` or `awk`, notes printed after the command such as `echo "exit=$?"`, searches with context lines, listings filtered by `grep`, results over 20,000 lines and small output pass through. Run `justless init --hooks --agent claude` again to add it.

- The Claude Code command hook keeps your permission rules in force. Claude Code checks its rules against the rewritten `justless run --hook -- …` command, so in Manual mode a `Bash(cargo test *)` allow rule stopped matching, every routed command asked again, and "Yes, and don't ask again" saved a rule that let any command through as `justless run -- COMMAND`; ask and deny rules for the original stopped matching too. When Claude Code reports its permission mode, the hook now reads the managed, user, project and local settings and judges the original command. A command that a deny or ask rule might match, or that sits beside an unreadable settings file, is left for Claude Code. One that allow rules cover is rewritten and approved, and in `auto` mode rewritten for Claude Code's classifier. One that no rule covers is rewritten only in `bypassPermissions` and `auto` modes; elsewhere it runs as written and the post-command hook compacts its successful output. `justless doctor` warns about allow rules such as `Bash(justless run *)` that let the agent run anything through Justless without asking.
- The Claude Code command hook reads "Yes, and don't ask again" rules where Claude Code saves them: in `.claude/settings.local.json` at the root of the Git repository, or of the main checkout from a linked worktree, for a session started in a subdirectory or a worktree. That file's allow rules count only where Claude Code's documentation says it keeps the file there, on Unix and outside the home directory, with the root, `.git` and `.claude` owned by the user; elsewhere only its ask and deny rules count. The agent benchmark harness pins Claude Code's user and managed settings under each run's home, so the machine's own permission rules no longer change what the hook routes there.

- A Claude Code Read with `offset` or `limit` that returns more than 150 lines of a source or Markdown file can become the outline rows around that window, with the revision, and `resume` lists it as `Outline FILE:A-B`. The same Read with `allow_large: true` returns the lines as they are, and Reads of at most 150 lines are never outlined, so following the outline's hint never meets another. Replayed on the 217 wider ranged Reads in local Claude Code transcripts whose files could be recovered exactly, the hook replaced 167 and cut them from 2,803,765 to 304,590 bytes. [Measurements](docs/benchmarks.md#ranged-read-outlines)
- Claude Code's post-edit hook adds a short note for the model, with the file, line, column and parser message, when a native Edit or Write leaves a file unparseable that parsed before, or adds a parse error inside its new text. An error that would not block `edit` says the parser may not know newer syntax, and C, C++ and shell files get no note. The tool result stays as it is, and other edits get no note. Run `justless init --hooks --agent claude` again to add it.
- In Claude Code, a routed `rg` that finds nothing, or a `git diff --exit-code` that finds a change, is no longer reported to the agent as an error. Claude Code judges exit status 1 by the program that starts the last statement, so the hook ends such a line with `&& test 1`, which Claude Code reads the same way and which keeps the command's exit status.
- `justless init --remove` takes Justless back out of a project: its instruction sections, hooks, status line, MCP entries and OpenCode plugin, for every client or those named with `--agent`. A file nobody edited since setup comes back byte for byte, other files lose only the Justless entries, and only directories setup created are removed. `--dry-run` shows each change first, a malformed file that mentions justless stops the removal before anything changes, entries in a form setup does not write are listed for editing by hand, and `--purge` also deletes `.justless/` and its `.gitignore` line. The home directory needs an explicit `--root`.
- Codex code mode is covered by the existing hook: Codex runs hooks for a shell command called from a code-mode `exec` script and matches it as `Bash`, so `init --hooks --agent codex` routes it as before and the script receives the compact output. Codex still gets no post-command hook, because its PostToolUse can replace a result only by rejecting a script's call or, for a direct call, without the exit status. [Details](docs/reference.md#install-and-configure-agents)
- `justless mcp` serves the read-only commands as MCP tools over stdio. `justless mcp --install` adds the server to Claude Code, Cursor, Gemini CLI, VS Code or Codex project config. The `log` tool returns at most 32 KiB per call and names the next page.
- When `CLAUDE.md` imports `@AGENTS.md` and `AGENTS.md` holds or gets the instruction block, `init` writes it there only and removes a copy from `CLAUDE.md`, which Claude Code loaded twice per request. `doctor` counts the import as Claude Code's block and flags a copy, and `init --remove` keeps the `AGENTS.md` block while Claude Code still reads it.

- `justless init --global` adds opt-in user-level hooks for Claude Code and Codex, merged into `~/.claude/settings.json` or `~/.codex/hooks.json`, that find the project per call from the hook input's directory. They leave alone the home directory, folders outside any project, projects whose `.justless.toml` sets `global_hooks = false`, and projects whose own Justless hooks already handle the event. `doctor` reports them and duplicate handlers, and `init --remove --global` restores the user files from setup's record or removes only the `--global` handlers.
- Hook kill switches: `exclude_commands` in `.justless.toml` lists commands, by their first words or a `^` regular expression, that every command hook and the post-command hook leave as written, and `JUSTLESS_DISABLE=1` makes every hook, including the OpenCode plugin, a no-op without uninstalling it. `justless rewrite "COMMAND"` prints what a client's command hook would do with a command and why, including Claude Code's permission verdict, without running or recording anything.

### Reporting

- `stats` reports bytes kept out of context by day and by command, with an estimated token count, full-log reopenings and runs whose output grew.
- `statusline` prints the current Claude Code session's estimated savings on one line, from hook-routed runs and replaced Read, Grep and Glob results. `init --statusline` adds it to the project's local Claude Code settings, `.claude/settings.local.json`, and never replaces an existing status line.

- `stats` reports bytes kept out of context by day and by command, with an estimated token count, full-log reopenings, runs whose output grew and each command family's preview budget with the reason for it.
- `stats` and the status line report savings net of what came back later. A run's output that `log`, `search`, `context --run`, `history TEXT`, `lookup --logs` or a `pack` printed again, from a shell or through MCP, is subtracted from that run's savings, so a 19,000-byte output shown in 364 bytes and then replayed whole counts as 364 bytes spent, not 18,636 saved. `stats` keeps the savings at first preview beside the net figure, and its existing `--json` keys keep their meaning. Whole replays recorded before bytes were counted are estimated at the archive's size and labeled, and proxy stats show the bytes marked for clearing, the bytes returned by archive recalls and the signed difference. After a replay, wide status lines show both initial and net estimates. Narrow lines prioritize the net estimate.
- `stats` estimates tokens with bytes-per-token ratios measured for each content type instead of bytes ÷ 4: code 2.57, JSON 2.22, prose 2.78 and logs 2.21, from Anthropic's token-counting endpoint for `claude-sonnet-5-5` (and identical for `claude-opus-5-5`) on this repository's own files and command output. Each run's archived output is sorted into one of the four types from its first 8 KB. Bytes ÷ 4 counted 56% to 70% of the tokens these models count, so on 73 runs archived in this repository's main checkout the estimate for 779,149 bytes kept out at first preview rose from 194,788 tokens to 317,766. The figures stay labelled as estimates, `--json` gives each type's bytes, ratio and sample size in `estimate_by_content`, and `scripts/token_calibration.py` repeats the measurement. The status line, `discover` and the proxy section still use bytes ÷ 4.
- The status line and `discover` estimate tokens at the 2.21 bytes per token measured for command output instead of bytes ÷ 4, so their figures agree with `stats`.
- `stats --sessions` adds what Claude Code's own session transcripts recorded for the workspace within `--days`: sessions, requests, and the input, cache write, cache read and output tokens the provider reported, by model, subagents and advisor calls included and each response counted once. It is printed apart from the savings as total usage, not savings, and reads only model labels and numbers.

- A local project registry in `$XDG_STATE_HOME/justless/projects.json` lists each project root, its repository and when it was last used, never output or command lines. `stats --all` totals every project, grouping a repository's worktrees and leaving temporary folders out unless `--include-temp` is given; `log`, `search` and `context --run` find a run made in another project; `doctor` lists the projects with hooks; and `init --remove --purge` drops the project from it.
- `discover` reads Claude Code transcripts for the workspace and lists shell commands that bypassed Justless, with labels and byte counts only.
- `discover`, `learn` and `stats` read Codex session rollouts too, including commands run from code-mode scripts. `discover` adds a Codex section with the bytes scripts received and the bytes they returned to the model, `stats` adds a line on how much Codex output went through Justless, and `learn` uses Codex commands as evidence, writing rules that only they support to `AGENTS.md`.
- `discover` counts a supported command that the Claude Code hook left as written under the permission rules and the mode the transcript recorded apart from one no hook saw, as "Supported, left to Claude Code's permission rules" (`left_by_permissions`), and suggests allowing the commands themselves rather than reinstalling hooks; `--plan` gives the bytes left per family. `doctor`'s "has not routed a command yet" note for Claude Code now says when the mode sessions start in, such as `default`, routes only commands that allow rules cover, and `doctor` names any Claude Code settings file that cannot be read or parsed, which stops the hook from routing in every mode.
